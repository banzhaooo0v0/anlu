# TD 修复与本次验证（2026-10-08）

工程：`E:/FPGA/workspace/anlu`。目标：`PH1P35MDG324`, speed 3。
虽然安装目录名是 `TD5.6.2`，实际工具启动信息为 **Tang Dynasty V6.2.168116**。

## 已修复

1. **器件库未初始化导致展开断言。** 批处理先执行 `import_device ph1_35p.db -package PH1P35MDG324 -speed 3`，再打开工程。运行目录必须为 `td_project`，保证相对路径及 CNN 权重初始化文件正确。
2. **双路版本在 Optimize Design 阶段崩溃。** 单路对照综合成功；改写 `video_in_dual` 为 idle/original/processed 状态机后，双路综合成功。内部崩溃的具体软件缺陷未确定，这里记录的是已验证的 RTL 改写规避方案。未通过删除原图通路规避问题。
3. **双 FIFO 输出对齐。** FIFO 读使能、地址和输出数据选择对齐，避免处理图突发末拍随状态机退出而误切回原图；请求覆盖末拍，DDR 停顿不增加计数/地址。帧首会结束未完成突发，错误帧重用上一写入槽。
4. **帧首像素可能被 FIFO 复位清除。** 两路 DDR 帧通知统一使用 AWB 的提前消隐标记；算法/打包器内部继续使用随首个有效像素对齐的标记。两路数据仍有不同流水线延迟，由独立 FIFO 吸收。
5. **去雾时序。** 原单拍暗通道、透射率、增益和饱和运算导致 Setup WNS `-17.566 ns`。改为 S0～S10 共 11 级寄存器，维持每拍四像素。首拍边沿 n 采样，输出在 n+10 更新。上/左边界屏蔽不存在的邻居，避免未初始化行缓存参与有效计算。Python 参考修正为对差值幅度移位，再恢复符号，与 RTL 的舍入一致。
6. **片上 RAM 超限。** 双路版本原占 `112/108` eRAM。AWB 延迟模块的地址在 `IMG_WIDTH/4` 回卷，却使用固定 2048×96 RAM。现在直接参数化原厂 RAM 包装器，1024 宽时分配 256×96，保留原读写模式和接口，综合减少 7 块 eRAM 至 `105/108`。未修改 CNN 权重或缩减双 FIFO 深度。
