# `dehaze_stream_96`：实时视频去雾

## 目标与接口

面向 PH1P35 的 1280×720 实时视频，输入/输出为 96 位四像素 RGB888 流。每个有效时钟处理四像素，无反压；S0～S10 共 11 级寄存器，边沿 n 采样的像素在 n+10 输出。有效、帧首、行末和旁路同步延迟。启用状态仅在有效帧首锁存。

仍使用两个 `IMG_WIDTH/4` 深度、8 位宽的暗通道行缓存，720p 下合计 5120 bit；不新增整帧存储、额外时钟或跨帧统计。摄像头域约 60 MHz 时理论处理能力约 240 Mpixel/s，是否满足整机实时输出仍以系统时序和实机验证为准。

## 算法

1. 求四个 RGB 像素全部通道的最小值，形成组级暗通道。
2. 对当前组、前两组及前两行求因果 3×3 局部最小值；缺失的上/左邻居不参与计算。
3. `t = max(MIN_TRANSMISSION, 256 - floor((dark*OMEGA_Q8 + 128)/256))`。
4. 额外增益 `k = min(48, floor((40*(256-t) + floor(t/2))/t))`，对应有效增益 `1 + k/64`。恢复混合系数为 `40/64`，上限为 1.75，步进为 1/64。
5. 每通道 `extra = floor((abs(I-A)*k + 32)/64)`，若 `I>=A` 则输出 `I+extra`，否则 `I-extra`，最后裁剪至 0～255。

倒数系数使用离线计算的常数 case 表，无运行时除法器。实际硬件把通道恢复等价改写为 `floor((I*(64+k)-A*k+(I>=A ? 32 : 31))/64)`，然后饱和。保留正负方向的半值舍入规则，输出与上述绝对差公式完全一致；全通道共用 `A*k`，消除 12 路绝对差运算。常数 `A` 的乘法显式使用移位加法，不占额外 DSP。

12 路像素乘积两两打包进 6 个 DSP：两个 8 位像素组成 `high<<15 | low`，共用 7 位增益 `64+k`，分别取出两个 15 位乘积。连同舍入，`255*127+32=32417<32768`，两路不会串扰；23×7 无符号乘法可装入 PH1P 的 27×18 乘法器。S9 仍为一拍，无需提高时钟或时分复用。

最初的 12 路逻辑乘法布局超限（21786/21216 slice），第二次使用绝对差乘法打包后资源可容纳但有一条 FIFO 写入 hold 违规，故继续压缩恢复逻辑。完整工程 DSP 预算由 34 增至 40，最终资源与时序以本次 TD 报告为准。`sim/check_dehaze_packing.py` 检查 4194304 种双通道输入/增益组合及另外 4194304 种大气光/像素/增益组合，分别证明打包无串扰、改写完全等价；`sim/generate_dehaze_gain_lut.py` 用精确有理数独立核对系数；图像与视频 RTL 测试使用独立的绝对差公式作参考。

算法没有加入空间低通或时域滤波，因此不会引入跨帧拖影；画面仍受组级窗口、固定大气光及浓雾信息丢失限制。颜色或自动曝光变化依旧可能影响画面，不能替代实拍验证。

## 参数

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `IMG_WIDTH` | 1280 | 宽度，至少 12，必须是 4 的整数倍 |
| `IMG_HEIGHT` | 720 | 图像高度 |
| `ATMOSPHERIC_LIGHT` | 240 | 大气光，合法范围 0～255 |
| `OMEGA_Q8` | 218 | 暗通道权重，合法范围 0～256 |
| `MIN_TRANSMISSION` | 64 | 透射率下限，合法范围 1～256 |

当前额外增益上限 48/64 与混合强度 5/8 固定在常数表中；若调整，需同步更新表、独立参考、测试及 TD 实现。

## 验证

十帧测试包含连续移动灰阶/彩色渐变、场景变化、空拍、帧边界、模式帧首锁存和饱和。另有两帧完整 1280×720 的去雾/旁路 → 双打包/FIFO → DDR 测试，逐项核对 691200 次写入。图像测试从实际 RTL 输出生成 PNG，原图宽度不能整除 4 时只向右复制边界补齐并在输出裁回原尺寸。
